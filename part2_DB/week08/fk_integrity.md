### Relationship Inventory and ON DELETE Justifications

| FK field             | In Table        | Refernces                         | Cardinality | ON DELETE | ON DELETE Justification                                                                                                                                                                                                                                                                                                                                         | ON UPDATE |
|----------------------|-----------------|-----------------------------------|-------------|-----------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-----------|
| group_id             | primate ids        | groups.group_id                   | 1:∞         | SET NULL  | This can be SET NULL because an primate can still exist if its group does not exist. For example, if group G and D were to become one new group, the records for G and D would be deleted but the primates still exist                                                                                                                                            | CASCADE   |
| observer_id          | observer sample | observers.observer.id             | 1:∞         | RESTRICT  | If an observer_id is deleted, for example they are no longer involved in the project, then we still need their data associated with their observer_id. Also, even if someone is not involved in the project any more we still want a record of the work they conducted there for crediting purposes and in the event they need to be contacted about their data | CASCADE   |
| observer_name        | observer sample | observers.observer_name           | 1:∞         | RESTRICT  | If an observer_name is deleted, we still need to know who collected what data. Deleting observer_name is thus blocked because doing so would orphan the related avistaje and focal data                                                                                                                                                                         | CASCADE   |
| observer_sample_id   | avistajes       | observersamples.observer_sample_id                   | 1:∞         | RESTRICT  | This is set to RESTRICT because observer_sample_id is basically the biggest umbrella of the dataset. If an observer sample is deleted, then all the data from that day will be lost. Additionally, the observer_sample_id is linked to geospatial data, so we need it in order to comb through gps records to create daily tracks and find points of interest   | CASCADE   |
| group_id             | avistajes       | groups.group_id                   | 1:∞         | SET NULL  | Similar to the primate ids table, if the group id deleted the data still exists and is meaningful. We can still use data without a group id and at times we even not that a group is unknown, so having it set to null instead of deleting all the data is safer.                                                                                                  | CASCADE   |
| avistaje_id          | focal samples   | avistajes.avistaje_id             | 1:∞         | RESTRICT  | Similar to the observer_sample_id, if avistaje_id is deleted then we lose a lot of information on who was seen, when they were seen, and where they went. This also connects to focal data which would also get deleted or made meaningless without the avistaje_id                                                                                             | CASCADE   |
| primate_id            | focal samples   | primate_ids.primate_id                | 1:∞         | SET NULL  | This can be SET NULL because even if an primate ID is deleted, data associated with the focal sample can still be useful. For example, we might not know WHO in group D was doing a specific behavior, but we can still say something along the lines of group D does X at this time.                                                                            | NO ACTION |
| focal_sample_id      | focal data | focalsamples.focal_sample_id      | 1:∞         | RESTRICT  | Every behavioral record needs to have a focal_sample_id. Deleting this information would make it very difficult to match where a behavior happened, what species did it, and what group did it. Therefore, it cannot be deleted                                                                                                                                 | CASCADE   |
| social_partner              | focal data | primate_ids.primate_id                | 1:∞         | SET NULL  | Just like with primate ID, we can still learn a lot about what a partner was doing even if we don’t know who they were. At times we cant tell who the partner is and so they get marked as unknown. Setting it to NULL upon deletion is safer to still get something from the data                                                                               | CASCADE   |
| nearest_neightbor_id | focal data | primate_ids.primate_id                | 1:∞         | SET NULL  | Again, like partner, if we don’t know exactly who the nearest neighbor is we can still get other insights from their proximity to the focal and general behavior. NULL is safer than just deleting records                                                                                                                                                      | CASCADE   |
| observer_sample_id   | gps points      | observersample.observer_sample_id | 1:∞         | RESTRICT  | This is VERY important. Each gps point has an observer sample associated with it so we can easily get say, Jack's gps points from June 5th and separate them from Nico's points from June 5th. Much of what we do also relies on this geospatial data, so restricting observer_sample_id ensures data is not lost.                                              | CASCADE   |
