# Database Table Field Specs

## groups table
| Field name   | Data type | PK/FK | NOT NULL | UNIQUE | DEFAULT | CHECK           | Rational                                                                                                                                                                                     |
|--------------|-----------|-------|----------|--------|---------|-----------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| group_id     | TEXT      | PK    | YES      | YES    |         | group_is != " " | Field is TEXT because group_ids are all letter (ex: Lagothrix G, Ateles MQ-1). This is the primary key because it will link to individual monkey ids, sightings (avistajes), and focal data. |
| species_name | TEXT      |       | YES      | NO     |         |                 | TEXT field to hold scientific name of species, labeled as not null because group_id is partially based on species name                                                                       |
| common_name  | TEXT      |       | NO       | NO     |         |                 | TEXT field to hold the common name of the species of each group, this one can be NULL because it is more of a nice to have for people who may                                                |

## identity table
| Field name | Data type | PK/FK                 | NOT NULL | UNIQUE | DEFAULT | CHECK                       | Rational                                                                                                                                        |
|------------|-----------|-----------------------|----------|--------|---------|-----------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------|
| animal_id  | TEXT      | PK                    | YES      | YES    |         | char_length(animal_id) >= 2 | Ids are unique names for known individuals and age-sex letter combination for unknown individuals, causing every id to be at least 2 characters |
| group_id   | TEXT      | FK -> groups.group_id | YES      | NO     |         |                             | Names and age-sex classifications are age specific, so need specific group_id too                                                               |
| age        | TEXT      |                       | YES      | NO     |         |                             | Ages are qualitative, such as juvenile, adult, infant                                                                                           |
| sex        | TEXT      |                       | YES      | NO     |         |                             | Sex is either male or female, so need it to be text field                                                                                       |

## obsevers table
| Field name          | Data type | PK/FK | NOT NULL | UNIQUE | DEFAULT | CHECK                                | Rational                                                                                                                      |
|---------------------|-----------|-------|----------|--------|---------|--------------------------------------|-------------------------------------------------------------------------------------------------------------------------------|
| observer_id         | INTEGER   | PK    | YES      | YES    |         |                                      | Surrogate key that assigns each observer a numeric value should name changes occur                                            |
| observer_name       | TEXT      |       | YES      | YES    |         |                                      | Primary key for this table, observer samples will each have an observer named associated with them to link back to this table |
| observer_first_name | TEXT      |       | NO       | YES    |         |                                      | Table holds names so needs to be text                                                                                         |
| observer_last_name  | TEXT      |       | YES      | NO     |         | char_length(observer_name_last) >= 2 | GPS files use last name of observer for identification, so need to be known for each observer                                 |
| primary_contact     | TEXT      |       | NO       | YES    |         |                                      | Primary contact can be phone number, email, or other means of communication, so needs to be text                              |
| institution         | TEXT      |       | NO       | NO     |         |                                      | Tracking each observers affilition to track collaborations                                                                    |

## observer sample table
| Field name         | Data type | PK/FK                        | NOT NULL | UNIQUE | DEFAULT | CHECK                               | Rational                                                                                                                         |
|--------------------|-----------|------------------------------|----------|--------|---------|-------------------------------------|----------------------------------------------------------------------------------------------------------------------------------|
| observer_id        | INTEGER   | FK -> observers.observer_id  | YES      | NO     |         |                                     | Need to link back to observer information                                                                                        |
| observer_name      | TEXT      | FK -> observers.observername | YES      | NO     |         |                                     | Need to tie data back to each known observer, hence why this links back to the observers table                                   |
| observer_sample_id | TEXT      | PK                           | YES      | YES    |         | char_length(observer_sample_id) = 7 | Each observer_sample_id is OS followed by 5 numbers, so I need there to be a limit on the length of each entry to prevent errors |
| date               | DATE      |                              | YES      | NO     |         |                                     | Each observer sample for each observeris from a different day                                                                    |
| gps_used           | TEXT      |                              | NO       | NO     |         |                                     | GPS devices are combination of letters and numbers, so needs to be text field                                                    |
| notes              | TEXT      |                              | NO       | NO     |         |                                     | Observers often take notes throughout the day, so need a text field to store those                                               |                                               
## avistajes (sightings) table
| Field name           | Data type | PK/FK                                   | NOT NULL | UNIQUE | DEFAULT | CHECK                      | Rational                                                                                                                                |
|----------------------|-----------|-----------------------------------------|----------|--------|---------|----------------------------|-----------------------------------------------------------------------------------------------------------------------------------------|
| observer_sample_id   | TEXT      | FK -> observersample.observer_sample_id | YES      | NO     |         |                            | Using this as foregin key to get the date of when the avistaje occurred                                                                 |
| avistaje_id          | TEXT      | PK                                      | YES      | YES    |         |                            | Each avistaje should be unique because each one indicate a sighting of a different primate species or group                             |
| group_id             | TEXT      | FK -> groups.group_id                   | YES      | NO     |         |                            | Need to call in list of groups to make selection on who was seen                                                                        |
| activity             | TEXT      |                                         | NO       | NO     |         |                            | Observers can mark the general activity of the group when they see them as text based descitptors (foraging, resting, vocalizing, etc.) |
| time_seen            | TIME      |                                         | YES      | NO     |         |                            | This is NOT NULL because each sighting needs to have a time associated with it to eventually link it to geospatial point data           |
| follow_data_included | BOOLEAN   |                                         | NO       | NO     | FALSE   |                            | This category is BOOLEAN because it is a simple true false of whether or not a group was followed after it was seen                     |
| time_left_lost       | TIME      |                                         | NO       | NO     |         | time_left_lost > time_seen | This field is allowed to be null because it only comes into play if the group seen was followed.                                        |
| duration             | TIME      |                                         | NO       | NO     |         | duration <= 24:00:00       | Follows should not last longer than 24 hours, so if there is follow data this check makes sure the end time was not entered incorrectly |
| notes                | TEXT      |                                         | NO       | NO     |         |                            | Observers often take notes within the avistaje table when collecting data                                                               |

## focal sample table
| Field name      | Data type | PK/FK                      | NOT NULL | UNIQUE | DEFAULT | CHECK                 | Rational                                                                                                                                                                |
|-----------------|-----------|----------------------------|----------|--------|---------|-----------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| avistaje_id     | TEXT      | FK -> avistaje.avistaje_id | YES      | NO     |         |                       | Need to link focal samples back to avistajes to eventually winnow down gps points                                                                                       |
| focal_sample_id | TEXT      | PK                         | YES      | YES    |         |                       | Each focal sample represents a unique period of behavioral data collection, so needs to be unique                                                                       |
| time_start      | TIME      |                            | YES      | NO     |         |                       | Time that the focal starts will be stored in HH:MM:SS                                                                                                                   |
| time_end        | TIME      |                            | YES      | NO     |         | time_end > time_start | Time that the focal ends will be stored in HH:MM:SS                                                                                                                     |
| animal_id       | TEXT      | FK -> id.animal_id         | YES      | NO     |         |                       | We want to keep a record of which individuals and age-sex classifications have behavioral data associated with them, ex: adult males do X more often than adult females |
| notes           | TEXT      |                            | NO       | NO     |         |                       | Observers often take notes within the avistaje table when collecting data                                                                                               |

## behavioral data table
| Field name                | Data type | PK/FK                             | NOT NULL | UNIQUE | DEFAULT | CHECK                                           | Rational                                                                                                                                                               |
|---------------------------|-----------|-----------------------------------|----------|--------|---------|-------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| focal_data_id             | INTEGER   | PK                                | YES      | YES    |         |                                                 | Each behavioral record within a focal sample needs to be individually identified, but observers do not assign this value, so it will be a surrogate primary key        |
| focal_sample_id           | TEXT      | FK -> focalsample.focal_sample_id | YES      | NO     |         | check_value_exists(focalsample.focal_sample_id) | Sometimes, data collection issues happen an a focal data record does not get assigned to a focal_sample_id, check makes sure each record has an id with it.            |
| time                      | TIME      |                                   | YES      | NO     |         |                                                 | Need the timestamp of when the behavior occurs                                                                                                                         |
| behavior                  | TEXT      |                                   | YES      | NO     |         |                                                 | Behaviors are coded as 3-4 letter combinations, for example RVA is resting vigilant at environment                                                                     |
| partner                   | TEXT      | FK -> id.animal_id                | NO       | NO     |         |                                                 | Sometime individuals are engaged in an acitivty like grooming which implies there is a partner                                                                         |
| partner_behavior          | TEXT      |                                   | NO       | NO     |         |                                                 | Need to mark that partner is either the actor or reciever of the behavior, which is text coded.                                                                        |
| time_begin                | TIME      |                                   | NO       | NO     |         |                                                 | Need time start of partner related activity, for example when a grooming bout starts                                                                                   |
| time_end                  | TIME      |                                   | NO       | NO     |         |                                                 | Need time end of partner related activity, for example when a grooming bout ends                                                                                       |
| nearest_neighbor          | TEXT      | FK -> id.animal_id                | NO       | NO     |         |                                                 | We record who is nearest to the focal at the time of the scan, but sometimes there is no nearest neightbor so it can be NULL                                           |
| nearest_neighbor_distance | TEXT      |                                   | NO       | NO     |         |                                                 | Nearest neighbor distances are ranges of distance, such as 0-5 meters.                                                                                                 |
| nearest_neighbor_behavior | TEXT      |                                   | NO       | NO     |         |                                                 | Just like focal behaviors, nearest neighbor behaviors are combination of letters.                                                                                      |
| proximity                 | TEXT      |                                   | NO       | NO     |         |                                                 | We also record the overall proximity of the focal, i.e. all individuals within 10 meters of the focal, this combines id, distance, and behavior, for example AM[0-5]F/ |

## gps points table
| Field name         | Data type | PK/FK                                    | NOT NULL | UNIQUE | DEFAULT | CHECK                                                 | Rational                                                                                                                                                                                                                                                         |
|--------------------|-----------|------------------------------------------|----------|--------|---------|-------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| gps_point_id       | INTEGER   | PK                                       | YES      | YES    |         |                                                       | Each gps point needs an individual ID in case it looks like the data might be the result of a satelite error (suddenly looks like we are 5km from out current position), so having a specific ID for each point will make it easier to find them and fix errors. |
| observer_sample_id | TEXT      | FK -> observersamples.observer_sample_id | YES      | NO     |         | check_value_exists(observersample.observer_sample_id) | Need to ensure that there the observer_sample_id associated with each gps point exists                                                                                                                                                                           |
| date               | DATE      |                                          | YES      | NO     |         |                                                       | Need to know the date the point was taken as a backup, can also use to just map all points from a given day                                                                                                                                                      |
| time               | TIME      |                                          | YES      | NO     |         |                                                       | Need the time of each point to link to behavioral data and range of time for follow data                                                                                                                                                                         |
| lat                | NUMERIC   |                                          | YES      | NO     |         |                                                       | All geographic data has decimal points associated with it, so need to be numeric                                                                                                                                                                                 |
| lon                | NUMERIC   |                                          | YES      | NO     |         |                                                       | All geographic data has decimal points associated with it, so need to be numeric                                                                                                                                                                                 |
| utm_x              | NUMERIC   |                                          | YES      | NO     |         |                                                       | All geographic data has decimal points associated with it, so need to be numeric                                                                                                                                                                                 |
| utm_y              | NUMERIC   |                                          | YES      | NO     |         |                                                       | All geographic data has decimal points associated with it, so need to be numeric                                                                                                                                                                                 |
